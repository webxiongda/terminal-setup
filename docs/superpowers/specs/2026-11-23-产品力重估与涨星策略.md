## ③ find=fd / grep=rg 别名冲突修法（P0）

### 根因
`configs/.zshrc` 用同名 alias 覆盖 flag 语法**不兼容**的系统命令：
- `find . -name a.txt` → fd 把 `-name` 解析成 `-n`（hidden）→ `error: unexpected argument '-n'`（管理员已实测）
- `grep -E 'a|b'` → rg 的 `-E` 是 `--encoding` 不是扩展正则 → 解析错误且语义被静默改变（更危险）

用户按 POSIX 肌肉记忆敲命令就失败，直接违背「开箱即用」。

### 推荐修法：删除冲突 alias（方案 A）
- 删除 `alias find='fd'`、`alias grep='rg'` 两行（`configs/.zshrc` 约 149–150 行）。
- `fd` / `rg` 本身名字就短，直接用即可；工具照常安装，只是不再劫持系统命令。
- **保留** `ls`/`ll`/`lt`/`la`/`cat`/`top`/`lg`（这些常用法兼容，不破坏肌肉记忆）。
- 否决「函数包裹做 flag 兼容」方案：复杂、脆弱、难测，违背 boring design。

### 文档影响
- README / README_CN 的 alias 表删 `find`/`grep` 行，新增一句：`fd` = 更快的 find、`rg` = 更快的 grep（**不覆盖系统 find/grep**，避免 flag 冲突）——把「不覆盖」转成「装不坏」的信任卖点。
- `docs/快捷键速查手册.md`、`content/site-content.json` 相关条目同步，跑 `scripts/check-content.sh` 防漂移。

### 验收
- `grep -nE '^alias (find|grep)=' configs/.zshrc` 无输出。
- zsh 交互下 `find . -maxdepth 1 -name '*.md'`、`printf 'abc\n' | grep -E 'a|b'` 均退出码 0 且输出正确；`command -v fd && command -v rg` 仍返回路径。
