## 0. 结论先行

owner 说「差点意思」不是文案问题，是**产品定位与分发**问题。三条核心结论：

1. **品类已过剩，缺少「为什么是你」**：GitHub 上 `terminal-setup` 同名仓库 **717 个**；和我们内容几乎同源、创建早 11 天的 `lewislulu/terminal-setup` 有 **739★ / 122 fork**，而我们 3★ / 0 fork。内容相近、结果差 246 倍 → 差距不在「写了什么」，在**发现路径 + 信任信号 + 差异化钩子**。
2. **「好用」有硬伤，必须先修**：全局 `alias find=fd`、`alias grep=rg` 让用户按肌肉记忆敲标准 flag 就报错，直接违背「开箱即用」主张。这是 owner 标注「第一重要」的项，属 P0。

## 4. 第 3 部分：alias 缺陷修法（P0）

### 4.1 问题本质

`configs/.zshrc:144-156` 用同名 alias 把系统命令替换成语法**不兼容**的现代工具：

| alias | 冲突实例 | 后果 |
|---|---|---|
| `find=fd` | `find . -name a.txt` → fd 把 `-name` 解析成 `-n`（hidden）等选项 → `unexpected argument '-n'` | 用户按 POSIX 肌肉记忆敲命令即报错 |
| `grep=rg` | `grep -E 'a\|b'` → rg 的 `-E` 是 `--encoding`，不是扩展正则 → `parsing flag -E` | 同上，且语义被静默改变（更危险） |
| `cat=bat` | `cat -n` 恰好兼容，但其他 GNU flag 未必 | 潜在风险 |
| `ls=…` / `top=…` / `lg=…` | eza/btop/lazygit 基本兼容常用法 | 可接受，保留 |

**核心原则**：不要用 alias 覆盖一个有**不同 flag 语法**的系统命令。用户学的是标准命令，不是你的替换品。

### 4.2 修法对比与推荐

| 方案 | 做法 | 优点 | 缺点 |
|---|---|---|---|
| A **删掉冲突 alias**（推荐） | 移除 `find`/`grep` 两行；`fd`/`rg` 本身名字就短，直接用；`cat=bat` 保留（常用法兼容） | 零风险、零学习成本、肌肉记忆全部恢复；改动最小 | 少两个「自动升级」的惊喜 |
| B 改短别名 | `alias f=fd`、`alias g=rg`（注意 `g` 常被用作 git 别名，可改 `alias ff=fd`/`alias rr=rg`） | 保留快捷入口 | 用户仍需记新键；`g` 有冲突风险 |
| C 函数包裹做 flag 兼容 | 检测 `-name`/`-E` 等 POSIX flag → `command find`/`command grep`，否则走 fd/rg | 两全 | 复杂、脆弱、难测，违背「boring design」 |

**推荐 A**：删除 `alias find='fd'`、`alias grep='rg'`；保留 `ls`/`ll`/`lt`/`la`/`cat`/`top`/`lg`（这些常用法兼容）。在 README 的 alias 表里补一行「`fd` = 更快的 find、`rg` = 更快的 grep（**不覆盖系统 find/grep**，避免 flag 冲突）」，把「不覆盖」本身变成卖点（呼应「装不坏」）。

### 4.3 对文档的影响

- README / README_CN 的 alias 表删去 `find`/`grep` 行，新增「现代命令速查」：`fd`、`rg` 直接可用，系统 `find`/`grep` 保持原样。
- `docs/快捷键速查手册.md` 同步（若含这两条 alias）。
- 文案源 `content/site-content.json` 若有相关条目一并更新，避免双端漂移。
