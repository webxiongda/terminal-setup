# terminal-setup 官网与视频讲解 实现计划

> **面向 AI 代理的工作者：** 必需子技能：使用 subagent-driven-development（推荐）或 executing-plans 逐任务实现此计划。步骤使用复选框（`- [ ]`）语法来跟踪进度。

**目标：** 为 terminal-setup 生成 3 个 VHS 录屏 mp4，并建一个纯静态中英双语官网内嵌视频，发布到 GitHub Pages。

**架构：** main 分支存源码（`tapes/` 录屏脚本、`site/` 静态站、`scripts/build-site.sh` 发布脚本）；mp4 只提交到 gh-pages 分支，main 通过 `.tape` 可重建。官网零框架，浏览器直接打开即可验证。

**技术栈：** VHS + ttyd + ffmpeg（终端录屏）；原生 HTML/CSS/JS；GitHub Pages（gh-pages 分支）。

**规格：** `docs/superpowers/specs/2026-11-22-官网与视频讲解设计.md`

---

## 全局约束

- 视频数量固定 3 个：安装 / 日常工具 / 主题与 Git；每个时长 20–60s，总计 ≤ 20MB。
- 纯静态站，无框架、无 npm 构建步骤；本地用 `python3 -m http.server` 验证。
- 官网中英双语，`data-i18n` 属性切换，缺文案回退中文。
- 视觉：Catppuccin Mocha 配色、等宽字体、终端极客风、响应式。
- mp4 只进 gh-pages，不进 main；`.tape` 脚本留 main 可重建。
- **全程禁止用 `read` 打开任何图片文件**（demo.gif/starship.png/zsh.png）；图片信息只用 `file`/`sips` 命令行。
- 不改 CLI 功能本身；commit 用中文 `feat:`/`docs:`/`fix:` 前缀；不主动 push main（发布只推 gh-pages）。

## 审查重点（Review Focus）

| # | 输入/条件 | 期望行为 |
|---|---|---|
| 1 | 本机缺 vhs/ttyd | 构建/录制脚本给出 `brew install vhs ttyd` 提示，不静默失败 |
| 2 | tape 里 `Require` 的工具缺失（如 lazygit/delta 未装） | VHS 早失败并指名缺哪个，先补齐再录，不产出半截黑屏视频 |
| 3 | 视频总大小 > 20MB | 降 `Set Width/Height` 或 ffmpeg 压缩，不放任仓库膨胀 |
| 4 | 浏览器不支持某视频格式或文件缺失 | `<video>` 显示占位文字/poster，页面其余部分正常 |
| 5 | 切换到英文时某 `data-i18n` 元素无对应文案 | 回退中文，不留空白 |

### 任务 1：录制环境准备与三个 tape 脚本

**文件：**
- 创建：`tapes/install.tape`、`tapes/daily.tape`、`tapes/git.tape`
- 创建：`scripts/record-videos.sh`

- [ ] **步骤 1：安装录制依赖**

运行：`brew install vhs ttyd`（ffmpeg 已在 `/opt/homebrew/bin/ffmpeg`）
验证：`command -v vhs && command -v ttyd && command -v ffmpeg` 三个都返回路径。
失败处理：若 brew 报错，记录错误并停下，不继续。

- [ ] **步骤 2：盘点 tape 里 Require 的工具是否齐全**

运行：`for c in zsh starship eza bat fzf zoxide lazygit delta fastfetch; do command -v $c || echo "MISSING:$c"; done`
验证：列出缺失项；缺的关键工具先 `brew install` 补齐（lazygit/delta/fastfetch 等），保证 tape 的 `Require` 不会早失败。
（覆盖审查重点 2）

- [ ] **步骤 3：编写 `tapes/daily.tape`**

基于现有 `assets/demo.tape` 复制扩展：`Set Shell "zsh"`、`Set FontFamily "Maple Mono NF CN"`、`Set Theme "Catppuccin Mocha"`、`Output site/assets/videos/daily.mp4`，演示 eza/bat/fzf/zoxide/fastfetch，每段 `Sleep` 留足观看时间。

- [ ] **步骤 4：编写 `tapes/install.tape`**

`Output site/assets/videos/install.mp4`，演示：克隆仓库 → `cd terminal-setup` → `./setup.sh --dry-run` 预览前几步；用 `Set Width/Height` 控制分辨率。不执行真实安装（避免污染环境）。

- [ ] **步骤 5：编写 `tapes/git.tape`**

`Output site/assets/videos/git.mp4`，演示：Catppuccin 提示符下的 git 状态 → `lazygit` 打开/浏览 → `Ctrl+C` 退出 → `delta` 风格的 `git diff`。若 delta 未配置为 pager，用 `git diff | delta` 显式演示。

- [ ] **步骤 6：编写 `scripts/record-videos.sh`**

内容：前置检查 `command -v vhs/ttyd/ffmpeg`，缺则打印 `brew install vhs ttyd` 并退出 1；然后依次 `vhs tapes/install.tape && vhs tapes/daily.tape && vhs tapes/git.tape`。
（覆盖审查重点 1）

- [ ] **步骤 7：本地实测 setup.sh（用户要求）**

开本地控制台，运行 `bash -n setup.sh`（语法）、`./setup.sh --dry-run`（应退出码 0、非交互不卡死）。记录结果。确认脚本正常后再录制。
注意：全程不用 `read` 打开图片。

- [ ] **步骤 8：运行录制脚本，生成 3 个 mp4**

运行：`bash scripts/record-videos.sh`
验证：3 个 mp4 存在于 `site/assets/videos/`，用 `ffprobe` 查时长 20–60s、用 `du -h` 查总体积 ≤ 20MB。画面无乱码（VHS 渲染不经模型，直接检查文件大小与 ffprobe 元数据即可；如需肉眼确认用本地播放器，不用模型读视频帧）。
（覆盖审查重点 3）

- [ ] **步骤 9：Commit**

`git add tapes/ scripts/record-videos.sh` 并提交 `feat: 新增三个 VHS 录屏脚本与录制脚本`（mp4 不进 main，加到 .gitignore）。

### 任务 2：静态官网（中英双语 + 视频卡片）

**文件：**
- 创建：`site/index.html`、`site/styles.css`、`site/app.js`

- [ ] **步骤 1：编写 `site/index.html`**

单页 6 区块：① Hero（标语 + 主视频 daily.mp4）② 特性亮点（从 README 提炼 6 条）③ 视频讲解（3 张卡片，各含 `<video controls preload="metadata" poster>` 指向 install/daily/git.mp4 + 讲解文案）④ 工具全家桶表格（eza/bat/fd/rg/fzf/zoxide/lazygit/delta/fastfetch）⑤ 快速开始（安装命令 + 复制按钮）⑥ 页脚 GitHub 链接。所有可切换文本加 `data-i18n="key"`；`<video>` 带 `preload="metadata"` 且写 `poster`/占位文字。
（覆盖审查重点 4）

- [ ] **步骤 2：编写 `site/styles.css`**

Catppuccin Mocha 配色变量（`--base:#1e1e2e` 等）、等宽字体栈、响应式（`@media max-width:768px` 单列）、视频卡片网格、按钮 hover、语言切换按钮样式。

- [ ] **步骤 3：编写 `site/app.js`**

实现 `i18n` 字典（zh/en），语言切换：遍历 `[data-i18n]` 按 key 填 textContent，缺失 key 回退中文；`localStorage` 记住选择。复制按钮：`navigator.clipboard.writeText` 复制安装命令并提示"已复制"。视频懒加载：`IntersectionObserver` 进入视口才设 `src`（若 preload=metadata 已足够可省略，二选一，保持简单）。
（覆盖审查重点 5）

- [ ] **步骤 4：本地验证官网**

运行：`cd site && python3 -m http.server 8000`，浏览器打开 `http://localhost:8000`。验证：3 个视频可播放、中英切换生效且无空白、复制按钮工作、手机宽度（DevTools 375px）不横向溢出。

- [ ] **步骤 5：Commit**

`git add site/index.html site/styles.css site/app.js` 并提交 `feat: 新增 terminal-setup 静态官网`。

### 任务 3：发布脚本与 GitHub Pages 上线

**文件：**
- 创建：`scripts/build-site.sh`
- 修改：`.gitignore`（忽略 `site/assets/videos/*.mp4`，因为视频只进 gh-pages）

- [ ] **步骤 1：编写 `scripts/build-site.sh`**

流程：检测当前在 main 且工作区干净 → 创建临时目录 → 复制 `site/` 全部内容 → `git checkout gh-pages`（不存在则 `git checkout --orphan gh-pages`）→ 清空工作区旧文件 → 复制临时目录内容 → `git add -A && git commit` → `git push origin gh-pages` → 切回 main。结尾打印 Pages URL。
（覆盖审查重点 1：脚本检测前置条件）

- [ ] **步骤 2：本地 dry-run 验证构建脚本逻辑**

用 `bash -n scripts/build-site.sh` 检查语法；人工核对流程不会误删 main 源码（在临时目录操作、gh-pages 分支才清空）。不实际执行 push。

- [ ] **步骤 3：执行发布**

运行：`bash scripts/build-site.sh`。验证：gh-pages 分支存在、远端 gh-pages 已更新、main 工作区干净且源码完好。

- [ ] **步骤 4：启用 GitHub Pages 并验证**

运行：`gh api repos/webxiongda/terminal-setup/pages -X POST -f 'source[branch]=gh-pages' -f 'source[path]=/'`（启用 Pages）。
验证：`gh api repos/webxiongda/terminal-setup/pages --jq .html_url` 得到 URL；curl 该 URL 返回 200；3 个视频 URL 可访问。
（覆盖审查重点 4：线上视频可加载）

- [ ] **步骤 5：Commit**

`git add scripts/build-site.sh .gitignore` 并提交 `feat: 新增官网发布脚本`（若 .gitignore 已存在则修改提交）。
